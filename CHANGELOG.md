# Changelog

Format based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), versioning per [SemVer](https://semver.org/).

## [Unreleased]

### Added
- **`aki__aiobox_write op=place_like` and `op=close_window`** (`scripts/aiobox-mcp.js`, AIObox guide v9 handoff): the new window takes the old one's place through `akipanel.placeLike(like)`, and the old window closes through `akipanel.closeWindow()`, never a CDP close; AIObox's refusal (busy, draft, offline) comes back verbatim. `op=state` also returns the `claims` and `flags` still in force from AIObox's agent files (guide v10: a flag names an account or a workspace, and one without `until` holds until unflagged).

### Changed
- **`aki__akidevrule_context` opens with a MANDATORY block, and its receipt no longer looks like a `[RULES]` line** (`scripts/rule-context-mcp.js`): a web chat has no aki-route-guard hook, and with the output opening `[RULES] practical-effective · sha256:…` models copied that as their receipt and skipped Reading the routed RULE/METHOD files. The output (an error too) now starts with the line `NO YAPPING AT ALL`, then one short BLOCKING paragraph (no rule Read, no action; reply opens `[RULES] agent (core) + <topics> (router)` naming only files actually Read; Read the matching route files before any Edit, Write or send; nothing is "done" without read-back evidence), then `context loaded: … · sha256:…`; the description says a receipt without `(router)` is a violation.
- **An AIObox handle is the window's lasting name** (`scripts/aiobox-mcp.js`, aiobox plan window-control D6): AIObox keeps `P#·W#` across its own and Chrome's restarts, so the "handles renumbered" warning after every AIObox restart is gone, as is the one for a handle restored onto a new tab; only an open tab whose handle changes (an AIObox fault) still warns. A handle retired at a handoff (`windows.json` `retired[]`, written by AIObox at `close_window` after `place_like`) leads to the window that took over, and the result says `resolvedFrom`; a loop is refused `retired_loop`. Tool descriptions, `wrong_window`, every `next` step and the guide fallback now name windows by handle; the chat id is the chat open in it now.
- **One `aiobox` call waits at most 50 s** (`wait_idle` `timeout`, `send` `wait`, `run_macro`): a client gives up on a tool call after about a minute and then gets nothing back, so `timeout=240` used to end in `-32001 Request timed out`. A longer wait is clamped, and a timed-out `wait_idle` says to call again (`next`). `wait_idle` defaults to 50 s instead of 120 s.
- **A credential value never comes back in a tool result** (`scripts/roots.js` `redactResult`, applied to every tool in `scripts/provider-registry.js`): `grep -r` over the data dir, a task log or a spilled output file used to return the access token, the passphrase or a client secret even though the files themselves are closed to the tools; each token-shaped value in the credential files, the passphrase and the panel token in `instance.json` now read `[redacted]`, also before an oversized output is cut and in the message of a tool that throws. Covered by `test/credential-redaction.test.js`.
- **A command the allowlist refuses says how to allow it without asking** (`scripts/shell-mcp.js`): the refusal of `run_cmd` and `task_start` names the entry to add (`"<bin>"`, `["<bin>", "<subcommand>", …]`, or bare `"git"` for a git write form), `shell.allowlist.added` in `~/.aki/mcpsv/setting.json` (read on every call, so it works on the next one) and panel section 6. A test holds that bare `git` in that file allows `git tag -f` and the other write forms at once.

## [3.0.0] - 2026-10-04

Major because `chrome_launch` no longer clones profiles and lost `refresh`: it opens only the clones AIObox keeps in `~/.aki/cdp/profiles/` (see Changed, Removed). A chat that cached AkiMCP's earlier tool list does not see the new AIObox ops: reconnect AkiMCP (AIObox macro Connect AkiMCP, option reconnect) or open a new chat.

### Added
- **`aki__aiobox_write op=new_chat window=<chatId>`: a fresh chat in the same tab**, through AIObox's `akipanel.newChat()` (the provider's new-chat URL, e.g. Notion `/ai`). AIObox's refusal (offline, still answering, a draft in the box) comes back verbatim; AkiMCP also refuses your own chat (`self_target`) and an AIObox without `newChat` (`no_new_chat`, use `op=new_window`). It returns once the new page's panel is online and shows an empty chat, with `chatId: null` and `previousChatId`, since the chat id exists only after the first `op=send`. The guide says when to use `new_chat` and when `new_window`.
- **`aki__aiobox op=state`: one call shows every AIObox window and returns the rules for acting in AIObox** (`scripts/aiobox-mcp.js`): each chat tab with `busy` and `account` (probed in parallel, 3 s each, a frozen tab is left out rather than guessed), each provider's macros, the server version and its `ops`, and `guide`, a short versioned list of steps (find yourself, name windows by chatId, send to another chat, wait before reading, eval last). The guide lives in the result, not the description, so a client holding an older schema still gets the running server's copy, and the description stays inside its budget.
- **`aki__aiobox op=whoami quote=`: an AI finds its own window**: it passes 20+ characters copied from its user's latest message; AIObox's chat reader is matched first, page text otherwise, a busy tab wins, and two chats showing the quote come back as `ambiguous` instead of a guess.
- **`aki__aiobox op=wait_idle`** waits until a chat stops answering (reader `busy`, polled every second, default 120 s, `timeout` up to 300) and returns its last messages; a page without an AIObox chat reader is refused with `no_adapter` rather than guessed from the DOM.
- **`aki__aiobox_write op=run_macro`** runs one of the window's AIObox macros (`macro`, `option`) through `akipanel.runMacro` and returns its final status; an unknown macro or option lists the valid ones, and a macro that reloads the page (whose status cannot come back) returns `timedOut` with the next step.
- **`aki__aiobox_write op=send`: a message to another chat is sent, not only filled in** (owner's rule: messages between windows are sent): it calls AIObox's `akipanel.live.send()` when the page declares `capabilities.send === 1`, which resolves only once the new user message shows in the chat and sends nothing when the chat is answering or the composer holds a draft. `wait=<s>` (up to 300) first waits for the chat to go idle and is refused with `busy` if it does not; the page's refusal comes back verbatim, another version is named, and an AIObox build without send is refused with `no_send` (compose remains for that case). The guide (v2) now says send.
- **`from=<your chatId>` on `aki__aiobox_write`**: sending or composing into one's own chat is refused (`self_target`).
- **`chrome_launch` warns while AIObox runs**: the result carries a `warning` that the profile belongs to AIObox and that a chat window opens through `aki__aiobox_write op=new_window` (`scripts/chrome-mcp.js`). It becomes a refusal once AIObox can open a stopped profile itself.
- **The tool-call log records what an eval does and who a call says it is** (`scripts/tool-call-log.js`): `evalKind` tags (`click`, `submit`, `keydown`, `dispatchEvent`, `fetch`, `innerText`) instead of the script, `from`, `macro`, and once per client the request header names (never their values).
- **`npm run tool-calls` reports how AIs drive AIObox** (`scripts/tool-calls-report.js`): from `tool-calls.jsonl` (`--days N`, default all) it counts the eval share and its `evalKind`s, browser tools pointed at an AIObox port instead of `aki__aiobox`, write ops sent before the client's first `state` / `whoami`, stale-schema `-32602` errors, calls from an older server version, and refusal codes; targets are in `docs/plan/aiobox-control-ops.md`. Covered by `test/tool-calls-report.test.js`.
- **Every tool declares MCP annotations** (`readOnlyHint`, `destructiveHint`, `openWorldHint`): 17 of the 38 tools are read-only by mechanism (18 while `agy_run` allows only `plan`), so ChatGPT stops asking to confirm them; every tool that can write still asks. `git` is marked open-world because `op=tags remote=` reaches the remote. Annotations are client UX and replace none of the allowlist, roots or SSRF guard.
- **Tool providers: tools of an app that is not installed are not served, and panel section 8 switches providers on and off** (`scripts/provider-registry.js`, `scripts/find-on-path.js`, `GET/POST /api/providers`). Detect runs once at boot: `agy` and `kiro-cli` on `PATH` (`PATHEXT` on Windows, nothing spawned), the Postman app (one `which`/`where` only when it is not at its standard path), a Chromium browser, `~/.aki/aiobox/`. A switch is stored as `providers.<id>.enabled` in `setting.json` (written atomically). `agy` and `kiro` start off, because each hands a whole task to another paid agent, and are switched on in section 8 (a setup that used them before 3.0.0 needs that one click); `rule`, `filesystem`, `search` and `shell` are always on. **Detect again** picks up an install without a restart. A client sees the change on its next tool list, usually a new chat. Contract: `docs/arch/provider-toolkit.md`.
- **`aki__aiobox` and `aki__aiobox_write`: reach an AIObox window by its handle** (`P7·W2`, any of `p7w2`, `P7.W2`, `P7-W2`, `P7 W2`) instead of looking up its port and target first (`scripts/aiobox-mcp.js`). `op=windows` lists every tab with its provider, profile and title; `op=read` returns the last chat messages through the page's `akipanel.live.chat()` when the page declares `akipanel.capabilities.chat === 1` (a reader error comes back as the tool error, verbatim, never as an empty chat), else the raw page text (`document.body`, since Notion has no `<main>`); `op=text` reads elements by selector; `op=screenshot`; `aiobox_write op=new_window` opens a new window (a new chat) of the same profile and provider through `akipanel.newWindow()`, the way AIObox's panel button does, and returns its handle; `aiobox_write op=compose` adds text to the chat box through `akipanel.live.compose()` when the page declares `capabilities.compose === 2` (Notion AI chat; it never sends, and another version is named in the error); `aiobox_write op=eval` runs JS; `op=read` also returns `account` (label, plan, login) as AIObox last saw it. The map `~/.aki/aiobox/cdp/windows.json` is read on every call, and a stale entry (target gone, or a title carrying another handle) is refused. Served only when AIObox is installed; the shared contract is in `docs/plan/IMPORTANT-akimcp-aiobox-contract.md` (both repos).
- **AIObox windows are named by what does not change, and a renumbered handle is caught** (`scripts/aiobox-mcp.js`): AIObox numbers windows only in memory, so a restart turns `P2·W11` into `P2·W1` and a message sent to the old handle reaches no window, or the wrong one, with no error. `op=windows` now returns `{ run, renumbered, tabs }`, each tab with its `chatId` (Notion `?t=`, ChatGPT/Grok `/c/`, Claude `/chat/`, Gemini `/app/`), `targetId` and `profileId`; `window` takes a handle, a chat id or a targetId; `expect` (targetId, chat id, or text of the url or title) refuses a handle that now names another tab; every op returns the `window`, `targetId`, `chatId` and `url` it used. Each call compares the map with the one seen before (kept in `aiobox-seen.json` in the data dir, so it survives an AkiMCP restart): a tab with a new handle, a handle on another tab, or a new AIObox run (`epoch` / `appPid` in `windows.json`, AIObox desktop 0.8.0) is reported as `renumbered`, and an op on an affected window carries a `warning` for 2 hours. With an AIObox that writes `epoch`, `op=windows` first asks it to re-read every window (`~/.aki/aiobox/cdp/windows.refresh`, answered within 5 s or the call fails), and an op whose window is missing or stale asks once before refusing. Contract: `docs/plan/IMPORTANT-akimcp-aiobox-contract.md` § Định danh bền.
- **Notion custom MCP connects with the passphrase, like Claude, ChatGPT and Grok** (`scripts/oauth.js`, `scripts/gatekeeper.js`, panel tab Notion under Web): Notion self-registers as a confidential DCR client on its exact callback hosts, authenticates with `client_secret_basic` or `client_secret_post`, gets the one shared access token plus its own refresh token, so Roll token no longer breaks it. Connect Notion this way, not with the access token pasted as a bearer (that copy stops working on every roll). New `POST /revoke` (RFC 7009) signs out only the calling client, the shared token stays; scope is carried and never widened on refresh; `/.well-known/openid-configuration/mcp` alias. Ported from PR #7 by @TheLucasHenry, without its per-connector access token (it contradicts the single shared token). Covered by `test/notion-oauth.test.js`.
- **AIObox and browser tool calls are logged without their arguments** (`scripts/tool-call-log.js`, called from `scripts/streamable-bridge.js`): each call of `aki__aiobox`, `aki__aiobox_write`, `aki__chrome_*` and `aki__devtools_*` appends one JSON line to `tool-calls.jsonl` in the data dir (time, client and agent, tool, `op`, `window`, `port`, ok or the first 200 chars of the error, duration, server version), never the text, script or url passed; rotated at 1 MB, one old copy kept. It answers which AI drove which window when a message lands in the wrong chat.
- **A call refused for invalid arguments (`-32602`) tells the AI its tool list may be stale** (`scripts/streamable-bridge.js`): a chat keeps the tool schema it loaded, so after an AkiMCP update it can send an argument the new schema no longer takes; the error now says to reload the tool list (new chat or reconnect) before retrying.
- **`test/tool-surface.test.js`** holds the served surface: a size budget for `tools/list` (baseline 27207 chars plus measured raises), annotations on every tool, descriptions ≤ 700 chars, every `aki__<name>` cross-reference resolving, provider switching and detection. `test/aiobox-mcp.test.js` covers handle parsing, the window map and the read fallback.

### Changed
- **`aki__aiobox op=read` carries `draft`** (the message box holds unsent text) when AIObox's chat reader reports it.
- **`aki__aiobox op=wait_idle` does not trust idle while a draft is in the box**: Notion then shows Submit in place of Stop, so `busy` reads false mid-answer. Meeting `draft: true`, it returns at once with `busy: false`, `draft: true` and a `warning`, without waiting further.
- **`aki__aiobox op=state` returns AIObox's own guide** (`scripts/aiobox-guide.js`): `guide` is `~/.aki/aiobox/guide.md` verbatim, frontmatter included, which AIObox writes from its bundled `shared/guide/aiobox.md` at every start, and `guideVersion` is its `version`. While the file is missing or does not open with `---\nversion: <n>\n---`, a short fallback (`guideVersion: null`) gives the few rules that matter and the web guide `https://aiobox.app/guide/aiobox.md`. The guide constant in `aiobox-mcp.js` is gone: the text now has one owner, AIObox.
- **`op=state` shows each window's `read`** (`live`, `queued`, `blocked` or `null`), from `akipanel.read`: how that provider's chat takes a message sent while it answers. The send rule in the fallback and in `docs/plan/aiobox-control-ops.md` names no provider: `live`/`queued` targets are messaged at once, `blocked` ones wait for idle (`op=send wait=<s>`), a draft is never touched. Since `op=send` still refuses a busy chat (unchanged), a busy `live`/`queued` target is reached for now by `op=eval`: `akipanel.live.compose(text)`, then a click on `[aria-label="Submit AI message"]` (Enter alone did not send on Notion; AIObox guide v7), only into an empty box, then a check that the user turns grew by one. A new window's profile is chosen by the guide (v8: on Notion, another of your accounts with the most usage left, only among profiles that already have a Notion window). The session-rotation hand-off there also starts by having the new chat compare `ops` with its own schema and reconnect AkiMCP (`run_macro macro=connect-akimcp option=reconnect`) when one is missing.
- **Without AIObox, `akidevrule_context` and the provider's not-installed reason carry one line** saying what AIObox adds (many AI chats and accounts side by side, messaging each other through AkiMCP) with the web guide link; once `~/.aki/aiobox/` exists the line is gone.
- **An invalid-arguments error (`-32602`) names the argument the tool does not take** (`scripts/streamable-bridge.js`): the bridge reads the tool's `inputSchema` and answers e.g. `takes no exprssion; its arguments are …`; the stale-schema hint (reconnect or open a new chat) is kept for errors where every argument is in the schema.
- **AIObox refusals say what to do next**: a missing window, a stale map, a renumbered handle or AIObox not running now ends with `(<code>; next: <one step>; akimcp <version>)`.
- **The panel and README recommend Cloudflare Tunnel over Tailscale Funnel** (`scripts/config-page.js` section 0, README "Exposing to the internet"): a Cloudflare tunnel holds a steadier connection, carries more bandwidth and answers from a larger global network. Funnel stays the path `npm start` sets up by itself, because it needs no domain; ingress precedence is unchanged.
- **`akidevrule_context` tells a session in an AIObox window to call `op=whoami`, then `op=state`** (was `op=windows`).
- **`npm test` finds the test files itself** (`package.json`): it runs every `test/*.test.js` and `scripts/postman/test/*.test.*` through Node's test runner, one file per process, one result line per file, instead of a hand-kept list of 32 commands that a new test could be left out of. `test/postman.test.js` (a runner for the Postman folder) is removed, `test/rule-context-mcp.test.js` is merged into `test/rule-context.test.js`, and eight tests that left a temp folder behind on every run now remove it.
- **Tool descriptions point at the cheaper tool**: `run_cmd` notes it stops after 10 s and that a dev server or watch fits `aki__task_start` (description trimmed to under 700 chars); `devtools_eval` notes that `aki__postman_eval` finds Postman's endpoint itself; the `devtools_*` no-session hint says an AIObox window is reached by its handle through `aki__aiobox`; `akidevrule_context` tells a session named by an AIObox handle (`P2·W1`, the start of its page title) to find and drive its own window through `aki__aiobox` / `aki__aiobox_write`.
- **The panel suggests the connector name `AkiMCP`** (was `Aki MCP Server from local Shell & FileSystem`), the name AIObox's connect macros recognize; `instance.json` also carries the running ingress `origin` and mode for every ingress, so AIObox takes the connector URL from one file (`scripts/instance-lock.js`, contract `docs/plan/IMPORTANT-akimcp-aiobox-contract.md`, held by `test/aiobox-contract.test.js`).
- **`chrome_launch` opens the profile clones shared with AIObox instead of cloning its own** (`scripts/chrome-profile.js`, `scripts/chrome-mcp.js`; contract `docs/plan/IMPORTANT-shared-cdp-profiles.md`). Profiles live in `~/.aki/cdp/profiles/<browser>-<profile>/` (`chrome-profile-14`; `AKI_CDP_PROFILES_DIR` overrides) and only AIObox creates them; `profile` takes `Profile 14` or the id, and a missing clone is an error that points at AIObox. Chrome's `SingletonLock` decides: a live owner is attached to through its `DevToolsActivePort` after a `/json/version` probe (`status: attached`, `owned: false`, `url` opens as a new tab), a live owner without a working port is refused, a dead or absent owner gets its stale lock and port files removed and a new Chrome (`owned: true`, launched with the marker flag `--aki-launcher=akimcp` so AIObox does not adopt it), and a lock from another host fails closed with nothing removed. `chrome_stop` without `pid` kills only a Chrome it launched; an attached session is only forgotten. The active-session port is probed before every use, and a dead one clears the session (one shared `resolvePort` for `chrome_*` and `devtools_*`). `chrome_profiles` also lists the shared ids. Tests cover each owner case with a fake CDP endpoint and a fake browser binary.

### Removed
- **`chrome_launch` `refresh` and the akimcp profile cloner** (allowlist copy, `.aki-clone.json`, `~/.aki/mcpsv/chrome-clones/`): it copied SQLite files while open, could rename a profile out from under a running Chrome, and duplicated AIObox's cloner. The old `chrome-clones` folder is no longer read and can be deleted.

### Fixed
- **`aiobox_write op=new_window` could return a window someone else had just opened**: for 1 s after a New window click AIObox's panel ignores `newWindow()`, and the next window to appear was the owner's. It now waits the rest out, counts that window as existing, and asks once more; a panel still resting is refused with `opening`.
- **`write_file` and `edit_file` dropped a file's permission bits** (`scripts/filesystem-mcp.js`): rewriting an existing file went through a temp file born with the umask's mode, so an edited script lost its exec bit and a `0600` file became `0644`. The temp file now takes the replaced file's mode before the rename. Covered by `test/filesystem-mcp.test.js`.
- **`initialize` reported server version `2.0.2`** whatever was installed (`scripts/tools-server.js`): it now reads the version from `package.json` (`scripts/version.js`), so a client and the tool-call log see the version actually running.
- **Unauthenticated crashes in OAuth** (found in PR #7): `client_id=constructor` / `__proto__` / `toString` resolved an `Object.prototype` member and killed the process; a `/register` body of `null`, an array or a scalar did the same. Both now return `400`. Rejected callbacks log only their origin, unknown grant types log as `unsupported`, request logs drop the query string.
- **`test/streamable-bridge.test.js` aborted the Windows test run with a libuv assertion at exit** (issue #8): the test now closes fetch's keep-alive connections and exits on the next turn. Passes on Windows 11 ARM64 with Node 22.14 (exit 0, no assertion).
- **A CDP socket that drops mid-call no longer kills the server** (`scripts/cdp-engine.js`): the short-lived `devtools_*` client now listens for `error`, so a target closing during `devtools_eval` / `devtools_screenshot` fails that call instead of raising an uncaught exception. From PR #9 by @QuachGia1994.
- **Windows finds 64-bit Chrome and Edge** (`scripts/chrome-profile.js`): the binary lookup tried `ProgramFiles(x86)` only; it now takes the first that exists of `ProgramFiles`, `ProgramFiles(x86)` and `LocalAppData` (per-user installs). From PR #9 by @QuachGia1994.
- **`test/task-mcp.test.js` runs on Windows**: it started `pwd`, a shell builtin with no binary there; it now runs `git log -1 --oneline` (PR #9 used `git rev-parse`, which an owner-narrowed allowlist may refuse). From PR #9 and PR #10 by @QuachGia1994.
- **`chrome_launch` says at once when the browser cannot start** (`scripts/chrome-profile.js`): a missing or non-executable browser binary was swallowed and the call waited 15 s, then reported a `DevToolsActivePort` timeout. It now fails immediately with the binary's path and the system error.
- **A client's cancel could end another client's request** (`scripts/streamable-bridge.js`): every client shares one internal session with request ids remapped, but `notifications/cancelled` was forwarded with the client's own id, which upstream is some other request or none. A cancel is now translated to the caller's own in-flight request, ends its wait at once (it used to hold the HTTP request until the 10-minute timeout), and is dropped when it matches nothing of that client's. The list of minted session ids, which grew by one on every `initialize` (claude.ai sends one about every 10 s per conversation), keeps the 2,000 most recently used. Covered by `test/streamable-bridge.test.js`.
- **The panel saves the shell allowlist and trusted zones atomically, like folders and limits** (`scripts/panel.js`): those two wrote `setting.json` in place, and a write cut short reads back as an empty file, which means the default allowlist and default folders. A request with a wrong panel token now answers in English (`wrong panel token: reload the panel…`) instead of `sai token`.
- **`npm run tool-calls -- --days` refuses a value that is not a number of days** (`scripts/tool-calls-report.js`): `--days week` or a missing value silently reported the whole log as if no filter were given; it now exits with the correct usage. The CLI is covered by `test/tool-calls-report.test.js`.
- **A frozen tab no longer holds a tool call for 10 minutes** (`scripts/cdp-engine.js`): a page that never answers left `aiobox` read/send/eval, `devtools_eval` and the Postman eval waiting for the bridge timeout. Every evaluate now gives up after 60 s with `the page did not answer within 60s (the tab is frozen, or the script is still running)`; `op=state` keeps its 3 s per tab through the same bound. Covered by `test/cdp-extensions.test.js`. The engine's unused `launch()` is removed.
- **`task_manage` reads at most 1 MB of a log tail and `kiro_read` refuses a prompt that starts with a dash** (`scripts/task-mcp.js`, `scripts/kiro-mcp.js`): `maxBytes` had no ceiling, so one call could buffer a whole log; a prompt beginning with `-` reached `kiro-cli` as a flag (`--trust-all-tools`) instead of text.
- **Windows: `grep`, `tail`, `cat`, `npm` and `npx` work after a default Git for Windows install** (`scripts/find-on-path.js`): the Git installer puts `git` on `PATH` but not the Unix tools in its `usr\bin`, so `run_cmd`, `task_start` and `search_content` answered "not found" until the user edited `PATH` by hand; akimcp now finds that folder from `git` and appends it to its own `PATH` at start. `npm` and `npx` are `.cmd` shims there, which cannot start without a shell; they now run as `node` plus the script the shim points at. A missing binary's message names both causes. Checked on Windows 11 with Node 22.14 and Git 2.47: `tail`, `grep`, `cat` through `run_cmd`, `search_content`, `npm -v`, `npm ls`, `npx --version`. `test/chrome-profile.test.js` skips its POSIX lock scenarios on Windows.
- **Windows: a Git Unix tool started through `task_start` (`tail -f`) exited at once with an empty log** (`scripts/task-mcp.js`): the task log was opened append-only, a handle those tools cannot write to. Each task run now starts its log file fresh, on every OS; a `taskId` started again no longer keeps the previous run's output.
- **Windows: the default shell allowlist lists only what `run_cmd` can start** (`scripts/allowlist.js`, `scripts/shell-mcp.js`): ten PowerShell cmdlets (`Get-Process`, `Get-CimInstance`, …) were on it, but `run_cmd` starts a binary without a shell and a cmdlet is not a binary, so each failed with `spawn … ENOENT`; they are removed. A command whose binary is not found now says so and names the cause. Checked on Windows 11 with Node 22.14. `test/output-shape.test.js` no longer asserts a POSIX file mode on Windows.
- **`.mcp.json` is ignored by git**: Claude Code's project-local registration holds the bearer token. From PR #9 by @QuachGia1994.

### Security
- **A request cut off mid-body no longer stops the server** (`scripts/gatekeeper.js`, `scripts/http.js`): an unauthenticated `POST` to `/token`, `/revoke` or `/authorize` whose connection dropped before the body arrived raised an unhandled rejection, which ends the Node process and disconnects every client. The gatekeeper now catches any failure of a request and answers that request alone (`500`, logged). OAuth bodies are capped at 64 KB (`413` beyond), and `/mcp` answers `400` to a JSON body that is not one object (`null`, an array, a scalar) instead of throwing. Covered by `test/gatekeeper.test.js`.
- **`notify_user` could run any shell command** (`scripts/system-mcp.js`): the message and title were pasted into an `osascript -e '…'` / PowerShell / `notify-send` command line after removing only `"` and `\`, so a single quote on macOS (or `$(…)` on Linux) ended the string and ran the rest, outside the shell allowlist. The text is now passed as data (script arguments on macOS, environment variables on Windows, argv on Linux) and no tool in this module starts a shell. Reproduced and re-checked on macOS; the Windows and Linux paths are covered by the argv test only. Covered by `test/system-mcp.test.js`.
- **`chrome_launch` refuses a `url` that starts with a dash** (`scripts/chrome-profile.js`): on a new launch the url is handed to Chrome as an argument, so `url=--gpu-launcher=<command>` was read as a Chrome flag and started a program. Covered by `test/chrome-profile.test.js`.
- **The tools no longer read or write akimcp's credential files** (`scripts/roots.js`): `tokens.json`, `passphrase.txt`, `oauth-client.json`, `oauth-dcr-clients.json` and `cloudflared-cred.json` sit under `~/.aki`, a default folder, so `write_file`, `edit_file` and `move_file` could mint a token or replace the passphrase, and `read_text_file` or `cat` put a live token into the chat. The file tools now refuse them, `run_cmd` and `task_start` refuse a command that names one, and `search_content` leaves them out of its results. `setting.json` stays readable and writable (owner decision, recorded in `docs/feat/security.md`). Covered by `test/trusted-zone.test.js`.
- **OAuth hardening** (`scripts/oauth.js`): a registered `client_name` is cut to 64 characters with control characters removed, so a newline in it can no longer forge a line in the log or bloat `oauth-dcr-clients.json`; the passphrase is drawn with `crypto.randomInt`, which removes a small bias toward `a`-`h`. `docs/feat/security.md` stated 32 symbols and 50 bits; the alphabet has 31, about 49.5 bits (every passphrase tried at 1,000 per second: about 26,000 years, calculated).
- **A trusted script zone no longer lets an interpreter flag carry code** (`scripts/shell-mcp.js`): `run_cmd` took the first argument without a dash as the script, so `node --eval=<code> <zone script>`, `node --require <any file> <zone script>` and `python3 -c <code> <zone script>` ran code the zone never held. The zone script must now be the interpreter's first argument; a call that needs an interpreter flag (`python3 -u script.py`) needs an allowlist row. Allowlist lookups also ignore inherited object keys (`constructor`, `toString`). Covered by `test/trusted-zone.test.js`.
- **`local_fetch` blocks link-local IPv6 and re-checks redirects** (`scripts/fetch-mcp.js`): the IPv6 patterns never matched, because a URL keeps the brackets of an IPv6 host (`[fe80::1]`), and `[::ffff:169.254.169.254]` reached the metadata address in IPv4-mapped form; a redirect to a blocked host was followed unchecked. The check now reads the host without brackets, covers `fe80::/10`, the mapped form and `fd00:ec2::254`, and runs on every redirect hop (5 at most). Other `fd..` addresses stay reachable, a tailnet and a home LAN use them. A response is read only up to 512 KB instead of whole and then cut. Not covered: a DNS name that resolves to a blocked address. Covered by `test/fetch-mcp.test.js`.

Windows support and the ChatGPT custom connector come from [PR #1](https://github.com/lacvietanh/aki-mcp-sv/pull/1) by **capybara** (`okdev888`), rebuilt onto the OS-agnostic architecture of `docs/plan/done/unify-windows-linux.md` — see `docs/plan/done/merge-pr1-windows-chatgpt.md` for what was adopted as-is and what was reshaped.

### Added
- ChatGPT custom connector on the same Funnel URL (contributed): RFC 7591 `POST /register` (dynamic client registration), public-client token auth (`none`), and allowlisted `https://chatgpt.com/connector/oauth/…` redirects. Registered clients persist in `~/.aki/mcpsv/oauth-dcr-clients.json`. Panel section 2 documents Claude and ChatGPT side by side. Claude's pre-issued Client ID/Secret path is unchanged.
- `scripts/agy-mcp.js`: dedicated MCP server for the `agy` CLI (wired into `mcp-hub.config.json`), replacing the generic shell route that shell-tokenized the whole command and could mis-split a multi-word `-p` prompt. Here `prompt`/`mode`/`model`/`effort`/`outputFormat` are separate `execFile` args, so no quoting step can get them wrong. Defaults to read-only mode `plan` and the fast wide-context discovery model; other modes must be opted into via `setting.json` `agy.allowedModes`, and `cwd` is enforced under an allowed root through the shared `resolveUnderRoot`.
- `scripts/open-browser.js`: small cross-platform "open default browser" helper (`open` / `cmd start` / `xdg-open` by `process.platform`), replacing the macOS-only `execFileSync('open', ...)` call in `start.js` — no new npm dependency added.
- `scripts/log.js`: shared timestamped logger. Gatekeeper request lines now carry an ISO timestamp + duration; `oauth.js` and `streamable-bridge.js` log each OAuth step, session open/close (with reason), stale-session 404s, and request timeouts — so a failed connect points at its exact cause instead of going silent.

### Changed
- OAuth metadata advertises `registration_endpoint` and `token_endpoint_auth_methods_supported: ["none","client_secret_post"]` (contributed). The token endpoint now authenticates the client per its registered method and binds each authorization code and refresh token to the client it was issued to.
- `agy-mcp.js`, `search-mcp.js`, `shell-mcp.js`: each MCP server and tool now advertises a human-readable `title` ("Antigravity CLI", "File Index" / "Find Path" / "Search Content", "Shell" / "Run Command"), so the connector UI lists them by name instead of by bare protocol id.
- Windows/Linux unification (`docs/plan/done/unify-windows-linux.md`): `package.json` `start` script no longer relies on bash-only `${VAR:-default}` syntax; `scripts/panel.js` folder picker (`osascript`, macOS-only) replaced with a manual "+ Add folder…" text input; `validatePaths` now uses `path.isAbsolute` instead of a hardcoded leading-`/` check, so Windows drive-letter paths pass; `scripts/config-page.js`'s `CLAUDE_DIR` build now uses `path.join` instead of manual `/` string concatenation; `scripts/search-mcp.js`'s path-depth sort in `walk`/`findPath` now splits on `path.sep` instead of `/`.
- `streamable-bridge.js`: per-request response timeout raised 30s → 10 min (`MCP_REQUEST_TIMEOUT_MS`) so long shell runs aren't cut off. (The 5-minute idle auto-close and the per-client session model it belonged to are gone entirely — see the single-session rewrite under Fixed.)

### Removed
- `scripts/chrome.js` and its 4 panel routes/UI (Chrome tab connect/restart/list/eval via CDP): macOS-only (`pgrep`, `osascript`) and already broken since Chrome 136 regardless of OS. The manual "paste this into the browser console" widen-chat-pane snippet is kept, folded into the Utilities section, since it never depended on Chrome automation.

### Fixed
- `streamable-bridge.js`: **the mass "client disconnected from MCP HUB" log is fixed at the root** (`docs/plan/done/bridge-session-churn.md`, Option B). Measurement (`docs/research/claude-ai-mcp-session-reinit.md`) showed claude.ai re-sends `initialize` with no `Mcp-Session-Id` every ~10s — 17 hub sessions in 4 minutes for 3 conversations — so the old per-client model spawned a throwaway hub session each time, producing thousands of connect/disconnect pairs. The bridge now holds **one** internal hub session for the whole process: every external client multiplexes onto it via JSON-RPC id remapping, and each `initialize` is answered locally from the cached hub result. The hub now logs one connect at boot and one disconnect at shutdown regardless of re-initialize frequency. Removed the per-client sessions Map, the `MCP_MAX_SESSIONS` cap, LRU eviction, and the diagnostic churn counters that scoped this fix — all compensating machinery the corrected shape no longer needs.
- `start.js` / `tailscale.js`: `npm start` now auto-starts Tailscale when it is stopped. `tailscale status --json` returns valid JSON even while the backend is `Stopped`, so `funnelStatus` previously reported the daemon as healthy and never brought it up — the public Funnel URL then closed every connection (`ERR_CONNECTION_CLOSED`). `funnelStatus` now reads `BackendState`, and `start.js` runs `tailscale up` before enabling the Funnel. A `NeedsLogin` state still requires manual login (surfaced in the log).
- Windows (contributed): `npm start` no longer dies on `spawn npx ENOENT` — the hub is resolved with `require.resolve('mcp-hub/dist/cli.js')` and run through `process.execPath`, and every child inherits an explicit `HOME`/`USERPROFILE` so the `${HOME}` placeholders in `mcp-hub.config.json` expand. Child processes spawn with `windowsHide: true`, spawn failures are reported instead of dying silently, path containment compares case-insensitively, and the panel's rule installer looks for `bash.exe` with a Git-for-Windows hint when it is missing.
- `shell-mcp.js`: the backslash is no longer treated as a dangerous character on any platform. `execFile` never invokes a shell, so it is an inert literal everywhere while being a legitimate path separator on Windows — one branchless rule rather than a per-OS one.
- Default shell allowlist widened with read-only commands: `sort`, `uniq`, `cut`, `diff`, `basename`, `dirname`, `realpath`, `which`, `date` everywhere, plus `where`, `findstr`, `tasklist`, `hostname` on Windows. `sed`/`awk`/`xargs`/`perl`/`python`/`env` are deliberately excluded — each can write files or execute an arbitrary program.
