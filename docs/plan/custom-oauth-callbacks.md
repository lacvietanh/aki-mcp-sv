# Custom OAuth callbacks — any AI with its own sign-in connects without a new AkiMCP release

Status: approved 2026-11-15; P1–P4 released in 4.2.0 (2026-11-17), P5 (live check with a real AI) open. Owner direction: "để mở rộng sự linh hoạt tối đa, ta cần tìm cách để người ta custom tối đa được, như cách ta đã mở rộng kiến trúc linh hoạt custom provider/macro bên aiobox vậy. và cả đợt akimcp v4 cho phép custom cả đống name prefix"; then "lên plan chi tiết … rồi thực hiện bằng các subagent akimaker … không hỏi lại gì nữa nhé". An advisor weighed the options and two challenger passes attacked the direction and then this design the same day; their findings are folded into the Decisions and Rejected below. D9's Remove wording corrected 2026-11-15 after review: a roll alone does not cut a refresh-capable client.

## Why

- `isAllowedRedirect` (`scripts/oauth.js:69`) is a code constant that reads no setting, so a new OAuth AI, or a provider moving its callback, needs a code edit, a test and a release. That happened 6 times across 5 releases: 1.1.0 ChatGPT, 1.2.0 and 1.2.1 Grok and Gemini (guessed callbacks, corrected the same day), 3.0.0 Notion, 3.1.0 Gemini's moved callback and ClickUp.
- Until the user upgrades, the AI shows only its own vague error: `/register` answers a bare `invalid_redirect_uri` (`scripts/oauth.js:335`) and the reason goes to the console alone.

## Decisions

| # | Decision | Why |
|---|---|---|
| D1 | **Callbacks are data, in one module.** New `scripts/oauth-callbacks.js` owns the built-in list `BUILTIN_CALLBACKS` (entries `{ name, match, value }`; Notion and Gemini become one `host` entry per hostname), the check for user entries, the reader of the user's entries, the matcher `matchCallback(uri)` (returns `{ entry, builtIn }` or `null`) and the refused list (D8). `oauth.js` keeps `isAllowedRedirect = (uri) => !!matchCallback(uri)` and drops its callback constants | One shape for built-ins and user entries, the way AIObox providers and the v4 custom names work; the callback rules live in one place |
| D2 | **The matcher compares what the browser is sent, not the raw string.** `/authorize` redirects to the parsed URL (`scripts/oauth.js:464,471`), so every match parses `p = new URL(uri)` first. Refused for every entry: a parse failure, a scheme other than `https:`, a username or password, a `#` anywhere in the raw string. `exact`: `p.href === value`. `prefix`: `p.origin === origin(value)` and `p.pathname.startsWith(path(value))`. `host` (built-ins only): `p.hostname` in the entry. | The raw `startsWith` let `https://chatgpt.com/connector/oauth/%2e%2e/x` pass while the browser lands on `/connector/x`; a raw `===` never matched an entry stored in parsed form (Gemini registers its callback with no trailing slash, `test/oauth.test.js:93-94`). Every legitimate built-in callback still matches; a `#` was never legitimate in a redirect URI (RFC 6749 § 3.1.2) |
| D3 | **User entries are `exact` or `prefix` only, with no name.** An entry is `{ match, value }`, `value` a string ≤ 2,048 chars that parses as a URL with `https:`, no username or password, no `#`, a hostname with at least one dot, no trailing dot and not an IP literal (dotted numbers, or `[`/`:` in the host); `prefix` additionally has a path longer than `/` that ends with `/`. Stored as `new URL(value).href` for `exact`; for `prefix`, origin plus path (query dropped). Duplicates by (match, value) collapse. Entries are labelled by their parsed host everywhere | `host` would trust every path and port of a shared host (a webhook or script service); a name chosen by whoever registered is the one way attacker text could reach the consent page as a trust label |
| D4 | **Storage: `setting.json` key `oauth.callbacks`** (an array), read fresh on every `/register` and `/authorize` through the one settings reader in `scripts/allowlist.js`, extended to also report a read error. Missing or non-array means no user entries; an invalid entry is skipped on its own with a reason; built-ins always apply. Writes go through `writeSettings` (atomic) and keep every other key | Settable by hand, by the panel, by a macro or by an AI's file tools, no restart (`plan/done/connector-setup-ux.md` D5: every rung automatable); a file without the key behaves like 4.1.0 |
| D5 | **`/authorize` re-checks the callback for every client**: a registered (DCR) client needs its `redirect_uri` among its registered ones and `isAllowedRedirect(redirect_uri)`; the static client and `reclaimClient` already check it | Removing a user entry then stops new sign-ins for clients registered through it; built-in clients pass as before (the only narrowing of a built-in, 1.2.0 → 1.2.1, left no surviving registration) |
| D6 | **The consent page names where the code goes**: "After you approve, the sign-in returns to **&lt;origin + path&gt;**", then "(built in: &lt;name&gt;)" for a built-in or "(added in your AkiMCP panel)" for a user entry. The page keeps exactly one `input[name=passphrase]` and one button whose text matches `Approve` | The owner's check before typing the passphrase, with no attacker-chosen text in the trust line; AIObox drives this page by that input and button (`docs/plan/done/IMPORTANT-akimcp-aiobox-contract.md`) |
| D7 | **The refusal tells the user what to do.** `/register`'s 400 carries `error_description`: "This AI's sign-in address is not allowed yet. On the computer running AkiMCP, open the control panel, section 1 → Web → Other AI (sign-in), click Add, then connect again." The console line keeps logging the origin only and ends with the same panel path | Some AIs display `error_description` (RFC 7591 § 3.2.2); the owner gets the fix where the failure shows |
| D8 | **Refused attempts are remembered in memory**, at `/register` (one row per registration with every callback that failed) and at `/authorize` when a callback is refused for the static client or a reclaimed client: the full parsed href of each failed callback (used by Add), shown as origin + path; the self-declared client name, labelled "name it gave itself"; first and last time; count. Newest 20 rows, deduplicated by their callback set, cleared on restart, never written to disk | The user never reads a log to find a callback; one Add can fix a registration that sent several callbacks (Gemini sends three); nothing attacker-chosen reaches the disk |
| D9 | **Panel tab "Other AI (sign-in)"** in section 1, Web tier, second after "Any HTTP chat", loading its data when opened and with a Refresh button. Contents: three steps (add the MCP URL as a custom connector in your AI; if it cannot connect, its refused sign-in address shows below, click Add; connect again and enter the passphrase; adding a new AI needs this computer once); **Refused since AkiMCP started** rows with **Add** (each failed callback as `exact`) and **Add as prefix** when a path has more than one segment (origin plus the path up to its last `/`), the confirmation naming the host; an empty state "Nothing refused since AkiMCP started. If your AI still cannot connect, it never reached AkiMCP: check section 0"; **Your sign-in addresses** with host, match, value, **Remove**, skipped entries with their reason, and a "setting.json cannot be read" notice when the reader reports an error; a manual form (match, address, Add). Remove's helptext: it stops new sign-ins through that address; to cut off an AI already connected through it, use Revoke & roll on it in section 7 Clients, or Roll & sign out all clients. When refused rows exist at page load, section 1 shows one line pointing to the tab | One click for the common case, full control for the rest; Remove's limit said where it is clicked (refresh records hold only `clientId` and `scope`, `scripts/oauth.js:668`); the user is pointed at the tab instead of hunting for it |
| D10 | **Panel API behind `x-panel-token`** like every panel route (`scripts/panel.js:563`): `GET /api/oauth-callbacks` → `{ entries, skipped, readError, refused }`; `POST /api/oauth-callbacks/add` `{ match, value }`; `POST /api/oauth-callbacks/remove` `{ match, value }`. Add validates with D3 and returns 400 with the reason when it fails. Add and remove are written to the security log (`oauth callback added: <match> <value>`) | A macro can set a connector up end to end; panel changes show in the security log; one route per action, like `/api/temp-token/extend` and `/revoke` |

Accepted risk, sized with `METHOD-proportionality.md`: anything that can write `setting.json`, an AI's file tools included (`docs/feat/security.md` § file tools reach akimcp's own data dir), can add a sign-in address; a code still needs the passphrase, typed by the owner on a page that names the destination (D6). Anyone can fill the refused list through the open `/register` (rate-limited per caller); a row adds nothing until the owner clicks Add, and its name is labelled as self-given. Reopen if an address added from the refused list turns out to be an attacker's, or the panel becomes reachable from another machine.

## Rejected

| Option | Why not |
|---|---|
| Any https callback behind the passphrase | Drops the only enforced check on where a code goes; `plan/done/integrate-gemini-grok.md:22` "do **not** loosen to a domain regex" |
| A signed or fetched remote list | Whoever controls the list widens every install at once; the most code; the owner stays the bottleneck |
| Approve an unknown callback on the consent page | The decision would sit inside the page a phisher sends |
| A manual Allow click as the safety gate | `plan/done/connector-setup-ux.md` D5: safety comes from where a key may go, never from leaving a step to the user; here the click is a shortcut, the address check and the consent page carry the safety |
| `host` entries for users | Trusts every path and port of a host; `exact` and `prefix` cover the real cases |
| A user-chosen entry name | The only path for attacker text into the consent page; the parsed host labels an entry |
| Remove also revokes grants made through that address | Refresh records do not store the callback; section 7 Clients already removes a client and its refresh tokens |
| Accept-and-hold unknown registrations as pending clients | Stores an attacker-chosen callback on disk before anyone approved it; the in-memory refused list gives the same one-click fix |
| A read-only list of built-ins in the tab | Nothing to act on; more to read |

Out of scope: OAuth with loopback or custom-scheme callbacks for desktop and CLI clients (RFC 8252), so Claude Code, Codex and Cursor stop needing a pasted Bearer token; a separate idea.
