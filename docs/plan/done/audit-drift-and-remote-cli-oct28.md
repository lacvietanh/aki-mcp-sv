## Decisions

**D1 — One exported SSoT for MCP server naming (`F1`, `F2`, `F7`, `pattern.A1`).**
- Decided: a new tiny module `scripts/mcp-name.js` exports `MCP_NAME = 'AkiMCP'` (display label for web connectors; `config-page.js` already injects it client-side), `MCP_SERVER_KEY = 'akimcp'` (machine key for Claude Code, Codex `[mcp_servers.akimcp]`, Cursor, the Claude desktop app, AGY and Postman) and `LEGACY_MCP_SERVER_KEY = 'aki-mcp'` (read only by the Apply cleanup and the tests). `scripts/config-page.js`, `scripts/panel.js` and `scripts/tools-server.js` import them, so `tools-server.js` takes `name`/`title` from the constants without importing the panel. `AGY_SERVER_KEY` is renamed outright to `MCP_SERVER_KEY` (importers `panel.js:8`, `config-page.js`), no alias. Only the Postman key `'aki-mcp-sv'` (`config-page.js:163`) is renamed; the repo name, the OAuth realm (`oauth.js:489`) and the user-agent strings stay · because the owner's complaint is that the unified name was never hard-referenced in the code that writes it, and both `'AkiMCP'` and `'akimcp'` satisfy the contract rule `name.toLowerCase().replace(/\s+/g, '').includes('akimcp')` in [IMPORTANT-akimcp-aiobox-contract.md](../IMPORTANT-akimcp-aiobox-contract.md#L15-L17) and `CLI-5` in [fact-agy-mcp-config.md](../../ref/fact-agy-mcp-config.md#L17) · rejected: (a) importing the constants from `config-page.js` into `tools-server.js` (pulls HTML helpers in); (b) an `AGY_SERVER_KEY` alias (two names for one value, `pattern.A7`); (c) a "zero `aki-mcp-sv` literals" rule (the repo name, realm and user-agent are not connector keys); (d) keeping `'aki-mcp'` and adding it to AIObox's `LEGACY` list (keeps two names alive) · reopen if: an external registry requires `McpServer` `name` to match a hyphenated package slug (`@akinet/akimcp` in `package.json` and `server.json` is already hyphen-free).
- CONSTRAINT: the key rename moves the tool namespace in Claude Code from `mcp__aki-mcp__*` to `mcp__akimcp__*`, so a permission allow-list naming the old namespace stops matching; the CHANGELOG entry must say so (open item `N1`). Duplicates with the claude.ai-synced `AkiMCP` connector cannot be removed from AkiMCP's side (runtime-only, see Verification).

**D2 — Remove the legacy `'aki-mcp'` entry during Apply only (`F2`, `flow.B6`).**
- Decided: `applyClaudeCode()` keeps its existing local-scope sweep (`projectsWithLocalEntry()`, `panel.js:53-73`) and adds `LEGACY_MCP_SERVER_KEY` to it (it never writes `akimcp` into project scopes, so none is cleaned); it runs `claude mcp remove` for the legacy key before adding `MCP_SERVER_KEY`. `applyCodex()` removes the legacy `[mcp_servers.aki-mcp]` table and its sub-tables (`replaceTomlTable` cannot delete, so a remove step is added) and then writes `[mcp_servers.akimcp]`. `applyCursor()` deletes `mcpServers['aki-mcp']` when writing `mcpServers.akimcp`. The copyable snippets carry no `2>/dev/null; …` shell chaining (it breaks Windows shells, `CLAUDE.md` § OS-agnostic); instead every hand-pasted snippet (Claude Code, Codex, Cursor, the Claude desktop app, Postman) carries one shared hint line, written once: delete any old `aki-mcp` entry first · because renaming the key without cleaning the old one leaves a user with both after Apply (`think.B5`), and a snippet cannot clean a file it only prints · rejected: (a) `2>/dev/null` chaining in the snippet; (b) requiring the owner to run `claude mcp remove aki-mcp` by hand in every project; (c) sweeping `akimcp` from project scopes · reopen if: never (one-way cleanup of a retired key).

**D3 — A "From another computer" block for the Claude Code, Codex and Cursor tabs (`F8`, `ux.A4`, `flow.B6`, `proportion.B3`).**
- Decided: the primary `On this computer (127.0.0.1)` block and its Apply stay the default in `tab-claudelocal`, `tab-codex` and `tab-cursor`. Each tab gains a `<details class="adv">` block (the class that exists, `public/panel.css:123-125`) titled `From another computer (via the section 0 address)`, rendered by one helper `fromAnotherComputer()` (not three hand-written blocks) with `url` = `${origin}/mcp` when `origin` is set, or the shared `noOriginNotice(reason)` ("Set up a public address in section 0 first, so another computer can reach this one.") when it is null; the snippet copies on click like the local ones, no Copy button and no Apply (Apply writes to this computer's disk only). `cursorJson` is extracted from its inline const (`config-page.js:164`) into a function taking `url` and the token, like `claudeCodeLines` and `codexToml`. The block says the token is stored in plain text on the other computer and that Roll token orphans that copy; the sentence at `config-page.js:444` is split so claude.ai / mobile / desktop app point to Web → Claude and the `claude` CLI on another computer to the block below · because it keeps Local-First for same-machine use, adds no tab (`ux.A1`) and no new exposure (the shared token is already shown for Buda, 365-day TTL `oauth.js:40`), and removes the manual URL edit · rejected: (a) switching the primary snippet to `${origin}/mcp` (routes local traffic over WAN); (b) a new top-level tab; (c) treating the remote CLI as a new connector (same connectors, same Bearer rung, only the URL changes) · reopen if: Claude Code CLI gains non-loopback OAuth DCR callbacks that remove the need for a Bearer header, or the first remote attempt fails (`docs/ref/fact-*` records the auth path per client once observed).

**D4 — Per-client revocation in Section 7 that names its collateral (`F9`, `flow.B6`, `ux.A4`, `ux.A6`).**
- Decided: `removeClientButton()` (`public/panel-client.js:410-425`) and `POST /api/clients/remove` (`scripts/panel.js:398`) distinguish two row states:
  1. **Never tokened** (`c.tokenAt == null && !c.signedIn`; `tokenAt` is set only by a grant, `oauth.js:641`): one `Delete` button, `roll: false`, no token warning (fixes the false warning at `panel-client.js:417`).
  2. **Every other row:** `Revoke & roll first` (`roll: true`) plus `Remove only` (`Sign out only` for `kind === 'static'`, `roll: false`). The server takes `roll === true` strictly, calls `removeClient(clientId)` first, then `rotateAccessToken({ revokeRefresh: false })`. The confirm text names the collateral truthfully: the rolled token retires the shared access token, so OAuth connectors renew it on their next request (ClickUp may need one reconnect, `CLAUDE.md` § Adding a connector) and Bearer clients (Buda, the local Claude Code / Codex / Cursor snippets) stop until the new token is set again. After a roll the page reloads through `reloadKeepingTab` (`panel-client.js:299-302`), because Section 1 snippets are server-rendered with the old token. `/api/security` and the AIObox contract are untouched (the field is additive).
  · because with one shared access token and per-client refresh tokens, `removeClient` plus a soft roll is the only per-client revocation, and saying what else it breaks is the difference between a tool and a trap · rejected: (a) per-client access tokens (rejected in `docs/plan/done/single-access-token.md` and `docs/plan/done/client-activity-and-security-log.md` D1/D5); (b) the claim that all other OAuth connectors "silently refresh" (contradicted by ClickUp and the Bearer clients); (c) making Roll the only or the primary one-click action · reopen if: AkiMCP moves to per-client access tokens.

**D5 — Filter and sort for the two Section 7 tables (`F10`, `ui.A1`, `ux.A1–A5`).**
- Decided: `renderTable()` (`public/panel-client.js:385-451`) gains opt-out column sorting (`sortable !== false`), cycling `asc → desc → server order`, with `fa-sort` icons on `th[data-sort]`, and a column may declare `sortValue(row)` so timestamps and counts sort as numbers while cells still render DOM nodes. The comparator `compareTableValues` lives in a separate classic script `public/table-sort.js` and is tested through `node:vm` (`public/panel-client.js` is a browser script nothing imports). Nil is `null`, `undefined` or `''` only (`0` is a value and a count); nil sinks to the bottom in both directions, then numbers, then case-insensitive `localeCompare`. The toolbar (text filter, `Refresh`) is static HTML in `scripts/config-page.js` and its state (filter text, sort key and direction) lives in a module variable, so `loadSecurity()` re-rendering after every action does not wipe it (`pattern.A9`). Both `Clients` and `Active now` keep their text filter (one toolbar helper makes the second table nearly free); `Clients` also has a status select (All · Signed in · Pending · Signed out); each toolbar shows "N clients" / "N callers", and "X of Y" only while a filter is active; every panel table sorts by its header · because the owner asked "lọc bảng, filter/sort" and the tables are bounded (`maxClients = 500`, 64 callers) · rejected: (a) client-side pagination or drawers (`coding.A2`); (b) dropping the status select, counts or per-table Refresh (the owner asked for the toolbar); (c) dropping the filter from `Active now` · reopen if: any panel table grows past 500 rows or moves to server pagination.
