# Instruction prompt — compact under 1500 chars + mandatory task/working.md workflow

## Goal
The pasteable "Instructions" prompt (panel section 6, generated by `buildPrompt()` in `scripts/config-page.js:304-316`) must: (1) stop repeating the rules-dir prefix once per ticked rule file, (2) stay under **1500 characters** because ChatGPT's custom-instruction field caps there, and (3) instruct every AI client to survey + confirm with the user before acting, then keep a resumable plan file per task. Claude's field is far larger, but one prompt serves both connectors, so the tighter limit governs.

## Problem — measured against the current code
`buildPrompt()` builds an array of lines joined by `\n`. Two concrete faults:
1. **Prefix repetition** (`config-page.js:310`): `picked.map((f) => RULES_DIR + '/' + f).join(', ')` prints the absolute `RULES_DIR` (e.g. `/Users/aki/.aki/akidevrule`, ~27 chars) once per file. With the 4 default rules that is ~80 wasted chars; with all ~19 rule files ticked it is ~500 wasted chars — the single largest source of bloat and the main reason the prompt can blow the 1500 cap.
2. **No length budget** — nothing measures the result, so a user who ticks many rules silently produces a prompt ChatGPT will truncate mid-sentence.

There is also no instruction about *how to work*: nothing tells the client to investigate and confirm scope before editing, and nothing establishes a place to record task state so a later session can continue.

## Decisions

| Issue | Decision | Why |
|---|---|---|
| Prefix repetition | Hoist the dir once: `read these rule files under <RULES_DIR>: index.md, RULE-agent-behavior.md, …` — bare filenames in the list | One occurrence of the path instead of N; role is unchanged, only the shape (`design.A1` — the path is one value stated once) |
| 1500-char cap | After building `lines`, measure `lines.join('\n').length`; the mandatory lines (answer-style, tools, task-workflow) always stay; the rules-loading line is the only variable-length one. Show a live char count under the textarea and a visible warning when over 1500 — **warn, never silently truncate** (a cut prompt would drop a rule the user chose). The user removes rules to fit | Keeps the guarantee observable without ever shipping a prompt the user did not see in full |
| Task workflow | Add one mandatory line (always present, not tied to the rules checkbox): survey + discuss + confirm scope with the user **before** acting, then write/maintain a plan at `$HOME/.aki/mcpsv/task/<id>/working.md`, updating it throughout so a later session resumes from it | This is the behaviour the owner wants enforced on every connected client, Claude and ChatGPT alike |
| Wording density | Rewrite every existing line to the deletion-test bar (`content.B2`) — the current lines are verbose; compression buys back the char budget the workflow line spends | The cap is a hard constraint, so every non-load-bearing word is a real cost |

## Target prompt shape (fill the `<…>` from the existing template vars)
Order, each a line in `lines`:
1. `ALWAYS answer short, dense, on point. Never speculate or invent — every claim needs evidence, every search a citation.`
2. *(only if rules ticked)* `At session start with MCP "<MCP_NAME>", first read <CLAUDE_DIR>/CLAUDE.md and these files under <RULES_DIR>: <bare, comma-joined filenames>, then follow them all session. Router: <CLAUDE_DIR>/skills/akirule/SKILL.md.`
3. `Every task: investigate and confirm scope with me before editing; then keep a plan at $HOME/.aki/mcpsv/task/<id>/working.md and update it as you go so a later session can resume. <id> = a short task slug.`
4. `Finding files/folders: always use find_path (one call, whole tree, returns folders, ~0.2s) — not list_directory level-by-level, not filesystem search_files. Use search_content for text inside files.`
5. `Run git/ls/grep in a folder via run_cmd with cwd (absolute, under <DATA_DIR>) — never cd or -C.`
6. `This server's own repo: <REPO_ROOT> — edit it there directly.`
7. `The chat's own sandbox tools (create_file/str_replace/view/bash_tool) write to a throwaway container, not this machine. For any path under <DATA_DIR>, only this MCP's filesystem tools touch the real machine — after writing, read the file back through the same MCP before calling it done.`

The subagent tunes exact wording to land the *default* (4 rules ticked) case comfortably under 1500 and to keep lines 1, 3–7 within budget even before rules are added.
