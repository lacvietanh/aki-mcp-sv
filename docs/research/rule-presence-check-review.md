## Result

- **R1 · Goal chain.** Immediate: a receipt that survived a compaction stops passing. Intermediate: rule text is in context at every gated write (core rules plus the rules for the file type). Ultimate: what web AIs write through AkiMCP follows the owner's rules, so the owner corrects less. Tensions: "3.x was the last reshaping" (`CLAUDE.md` § Stable core) vs new gate machinery; "low context cost" vs "cannot be cheated". The plan measures only the mechanism (its F13); its outcome measure U5 has no data path (R9).
- **R2 · The larger, better-evidenced gap is the plan's F5 (rules for the file type are never delivered), not compaction.** A web chat gets only the core files once (`project-rules.js:79`, `PROJECT_FILES`); `RULE-coding.md`, `RULE-pattern-core.md`, `RULE-docs.md` arrive only if the model reads them. On Claude Code, sessions that edited the file type read its rule: coding 1%, docs 56%, test 0% before the route gate; 94%, 97%, 60% after (`second_hop_audit.py`, 2026-10-21). Inference: a web chat with no delivery at the write sits near the "before" column for code, compaction or not. Plan D4 closes this and needs neither D1 nor a ledger: the receipt is a content hash (`rule-context.js:206-207`), so today's D23 `extraFiles` chain (`rule-gate.js:78-84`) can carry route files unchanged. Cost: one push per file type per chat (coding+pattern 21,578 B, docs 19,358 B), no tool-definition change, restart only. `RULE-release.md` is 49,216 B, over the 32 KiB cap (`project-rules.js:11`), so it is only named.
- **R3 · Compaction loss is real but unquantified; check frequency estimated.** Notion is 5,362 of 9,189 calls (58%); 299 Notion `baggage` values, median span 1.75 min, 66 holding an `akidevrule_context` call, matching "baggage names the turn"; no per-chat id on the wire (plan F3 holds). 78 turns have ≥ 20 calls (top: 175 calls over 42 min, one context call); 21 span more than 15 min. Compaction inside one long turn is plausible against a 240k window (unverified). Estimate, not measured: the check would fire 10–46 times a day in Notion, +2.4–10.8% of Notion calls at +2 calls per check, or +1.2–5.4% at +1 call (R5). The plan's F2 is a single observation.
- **R4 · D1 (one receipt per issuance) contradicts current code at three points the plan does not name.** (a) `rule-context.js:110-111,216` answers `unchanged` only when `knownReceipt` equals the content receipt; a nonce receipt never matches, so D8 needs step 2 to map it to its stored content receipt first. (b) After a restart the map is gone, so every chat's next context call returns the full ~58 KB, where today the same content gives `unchanged`. (c) `MAX_ISSUED` = 200 (`rule-gate.js:10`): identical receipts no longer collapse, and at ~275 context calls per 6.3 days an idle receipt is evicted after about 4.5 days (estimate). The regex claim holds (`rule-context-mcp.js:49`, `rule-gate.js:9`).
- **R5 · D6 (`proof` on `akidevrule_context`) contradicts the one-time definition change.** P3 bundled every definition change into one release (`akimcp-tool-refactor.md:15`), shipped in 3.0.0 (`CHANGELOG.md:58`); step 5's "bundled per P3" points at nothing, and D6 brings a new wave of "Always allow" prompts and reconnects against `CLAUDE.md` § Stable core. The rejected alternative wins: the gated schema is a bare `z.string().optional()` (`rule-gate.js:11`), so `receipt="sha256:<hex> <8 words|none>"` needs no definition change; a pass costs +1 call instead of +2; D9's old-schema deadlock disappears; the fail path reuses the D23 result. The plan's "hard to read in a log" is void: the call log never stores argument text (`tool-call-log.js:1`). Parse `^(sha256:[a-f0-9]{64})(?:\s+(.+))?$`; a second malformed reply counts as `none`.
- **R6 · D5 (the check) holds in principle; four details are off.** (a) The Cases row says a passed check costs +1 call; it costs +2 as written. (b) "6 of 8 position by position" fails the whole answer on one dropped word; use an in-order common subsequence ≥ 6 of 8. (c) The anchor must be unique across every file delivered to the receipt, not within one file. (d) One answer marks every overdue file checked, so the check detects a compaction rather than proving each file; one clock per receipt plus the shas of delivered files gives the same behaviour as D2's per-file timestamps. Holds: a summary cannot hold the answer, and the token case against a blind push (58,535 B assembled with this repo's `workingPath`, 50,785 B without).
- **R7 · D7 (leak scan) is oversized.** The leaker is a helpful model looking the answer up, no motive, damage at most 15 more minutes without rules. A content scan must cover every read tool's output (`aki__git`, `kiro_read`, `read_multiple_files`, not only `search_content`). Cheapest sufficient control: while a check is pending, a read-tool call whose path input touches the rules directory or the named file voids the proof and is logged; the wrapper slot exists (`rule-gate.js:138-149`).
- **R8 · D10 (log each check) cannot be implemented as written.** The call log is built at the bridge from the response (`tool-call-log.js` `buildLogEntry`); `errorCodeOf` matches only `(code; next: ` (`tool-call-log.js:19,59`), so 0 of 9,189 lines carry a `RULE_*` code, and a check reply or a D23 push is not an error, so nothing records it; D23's own reopen trigger has been unmeasurable since it shipped. The change belongs in `tool-call-log.js` (read a leading `RULE_[A-Z_]+` token from the first text line, error or not), which the plan omits.
- **R9 · U5 (the outcome measure) has no data path; a confounded baseline exists.** Basic-level log lines carry no paths and 166 of 167 commits since 2026-10-01 carry the owner's identity, so a write cannot be traced to a chat or its check state. Free instrument: web chats write `~/.aki/mcpsv/task/<slug>/*.md`; `scythe.py` finds [WRAP] in 31 of 143 such files modified in 21 days (22%). [WRAP] breaks a core rule the context call delivers, so this measures the compaction part. Confounds: ignoring vs forgetting are not separable; authorship assumed to be web chats.
- **R10 · D4's test plan breaks `test.B1`.** "Its test feeds the deployed map" reads the real HOME. Fix: a fixture map using every field in the default suite; the deployed map only in a separately named `*.live.*` suite.
- **R11 · `CLAUDE.md` constraints.** Single shared session: not violated (the ledger is keyed by an in-band receipt, not the transport session), but it is per-chat state with a 200-entry cap (R4c). AIObox never drives a change: holds. Stable core: D6 conflicts (R5); the rest is a core need. Native → guide → tool: text alone fails (plan F7, F11), so a gate is justified, in its cheapest shape (R5).
- **R12 · An irreversible tail the plan does not reach.** The owner's `run_cmd` allowlist grants `git restore`, `reset`, `add`, `commit`, `rm`, plus `rm`, `node`, `python3`. A compacted model that forgot `agent.B3` can discard other sessions' uncommitted work in the shared checkout; the presence check does not prevent it (15-min gap; present is not applied). `proportion` B1 gives this tail its own control: refuse `reset --hard`, `restore` without `--staged`, `checkout --`, `clean -f`, `stash` in `run_cmd` arguments. Outside this plan.
- **R13 · Critique.** Steelman "push full rules every 15 min": uncheatable and simplest, but ~58 KB per 15 min per chat is 12–19% of a 240k window over a 42-min turn and hastens the next compaction; the plan's rejection holds. Steelman "rules in the client's own instructions": never compacted, zero AkiMCP change; a short stable line complements a gate (F11 predicts about half compliance), owner/AIObox-side. Transcript detection and session binding: correctly rejected. "Proof on every gated tool": wins once it rides in the `receipt` string (R5). New alternative, lint at the write: the only option acting on the outcome; needs a reimplementation that drifts from `scythe.py`, not now. Shrinking the core (`SKILL.md` 15.5 KB + `CLAUDE.local.md` 7.6 KB of 58.5 KB) makes every reload cheaper, AkiDevRule-side. Attack on the favoured option: each AkiDevRule edit to a route file makes the receipt STALE and forces a full reload (small marginal cost, unmeasured). Pre-mortem: checks almost always pass, breaches persist because present is not applied, U5 never computed, D6 forced a reconnect wave and stale-schema seats lived on the D9 reload path, the route-map interpreter met an unknown field and fell back silently, and a `git reset` in a compacted chat destroyed work anyway (R12). Second order: +1.2–10.8% Notion calls (latency and credit unverified); Claude Code clients get checked twice; a failed check pushes 58 KB, which brings the next compaction closer, which fails the next check.
- **R14 · Proportionality.** Reach: every web chat writing through AkiMCP (Notion 58% of calls, 224 Notion turns with gated calls in 6.3 days). Capability: forgetting; a lookup leak by a helpful model. Motive: none. Blast radius: rule breaches in files, recoverable through git, except R12. Route push = rung 2 ✓; check = rung 2/3 ✓ at +1 call; content leak scan = rung 2 against no adversary, over-built; D6 = a definition change for what a string can carry, over-built. Smallest version with most of the value: D4 on the existing D23 chain plus the log fix (R8).
- **R15 · Recommendation: build a reduced version, in two stages.** Stage A now: D4 only, carried by today's D23 `extraFiles` chain; route-map interpreter with fixture and live tests (R10); `tool-call-log.js` records `RULE_*` codes and a non-error push token (R8); docs; no tool-definition change. Stage B after A ships and the R9 baseline is recorded: D1 with the `knownReceipt` mapping and the restart behaviour stated (R4); D2 as one clock per receipt plus delivered shas (R6d); D3 replaces the chain; D5 with the proof in the gated call's `receipt` string, in-order ≥ 6/8, anchor unique across delivered files (R5, R6); D7 as a path flag (R7); D8 one line; D10 via the log fix; drop D6 and D9. Fix in either stage: the Cases "+1" (R6a) and the stale F8 sizes (`RULE-agent-behavior.md` 25,673 B; context 58.5 KB with `workingPath`).

**Verification:** code facts by reading the cited lines (spot-checked by the caller: `rule-gate.js:9-11`, `tool-call-log.js:19,59`, `CHANGELOG.md:58`); log counts by in-shell aggregation over the call-log files; sizes by `wc -c` and in-process `assembleRuleContext`; Claude Code read rates by a `second_hop_audit.py` run on 2026-10-21; [WRAP] baseline by `scythe.py --all` over 143 files. Unverified: that `baggage` maps to exactly one Notion turn; how often Notion compacts and whether it drops tool results; the check-frequency range; the credit and latency cost of extra calls; that the task markdown is written by web chats; that verbatim recall of 8 words holds across clients; every token figure (≈ 4 chars/token).
